# Администрирование сервера Solbreaker

[Быстрый запуск](../README.ru.md)

## Комплект выделенного сервера

В alpha.8 для Windows x64 предусмотрен архив
`Solbreaker-<версия>-server-windows-x64.zip` с Python, нативной физикой и TUI.
Для Linux x86-64 есть `Solbreaker-<версия>-server-linux-x86_64.zip` с
пятью готовыми библиотеками физики. Нужны glibc 2.39 или новее, CPython 3.11
с модулем `venv`, а для первой установки зависимостей нужен доступ к PyPI.
Например, подходит Debian 13 с отдельно установленным Python 3.11.
Для другой версии Python или более старой glibc можно использовать
архив `source` и собрать библиотеки по инструкции для Linux.

### Выборочная загрузка ресурсов из Steam

Если совместимая папка Blitz уже есть, передай её установщику и переходи
к запуску. Для отдельной машины можно скачать серверные ресурсы
через [DepotDownloader](https://github.com/SteamRE/DepotDownloader#parameters).
В списке 7 306 файлов, около 1,06 ГБ на диске. Туда входят геометрия и
параметры техники, данные карт и EXE для проверки сборки. Для запуска игры
на другом ПК нужна полная совместимая сборка.

Выполни в PowerShell из папки комплекта с `DepotDownloader.exe` в текущей папке.

```powershell
.\runtime\python\python.exe tools\server_depot.py filelist --output server-files.txt
.\DepotDownloader.exe -app 444200 -depot 444202 -manifest 7369903689024228557 -filelist server-files.txt -dir server-resources -username ТВОЙ_ЛОГИН
.\runtime\python\python.exe tools\server_depot.py verify server-resources
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1 -Game .\server-resources
.\tools\start-server.cmd
```

Вводи пароль и Steam Guard в самом DepotDownloader по его запросу.
Проверка сравнивает каждый скачанный файл с каталогом SHA-256. После
установки сохрани папку `server-resources` на месте. Для управления из
терминала открой `launch-tui.cmd`.

На Linux используй `./DepotDownloader` с теми же аргументами загрузки и
`python3 tools/server_depot.py` для списка и проверки. Затем из каталога
серверного комплекта выполни:

```sh
python3.11 tools/setup.py --game ./server-resources --skip-build
./start-server.sh --state data --log-file data/server.log
```

Установщик создаёт `.venv` и проверяет загрузку всех пяти библиотек.
Для управления из терминала открой `./launch-tui.sh`.

## Подключение клиента

Экспортируйте публичный профиль сервера и импортируйте его в совместимом
лаунчере клиента. Файл содержит адреса, публичный ключ входа и при настройке
собственного TLS CA — его публичный сертификат.

```sh
.venv/bin/python -m solbreaker export-connection --state data --output connection.json
```

Закройте игру перед импортом профиля в подготовленный клиент.

```sh
.venv/bin/python -m solbreaker import-connection \
  --lab /path/to/prepared/client --connection connection.json
```

Состояние аккаунтов хранится в SQLite внутри `data/private/`. Закрывайте
сервер штатно через Ctrl+C перед обслуживанием или резервным копированием
состояния. Одновременный запуск двух серверов на одном состоянии отклоняется.

## Регистрация

В штатной форме «Создать аккаунт» вводятся почта, ник и пароль.
Имя сохраняет выбранный регистр, проверка занятости выполняется без учёта
регистра. Допустимы 3–24 латинские буквы, цифры и подчёркивания.
При нажатии «Создать» проверяется занятость почты и имени.
Клиент получает сообщение с причиной отказа.
Успешная регистрация сразу переходит ко входу в игру.

Подготовленный клиент можно настроить отдельной командой при закрытой игре.
Она адаптирует штатные UI-ресурсы закреплённой версии и пропускает выбор
страны. Почта используется как логин. Подтверждение по письму не требуется.

```sh
.venv/bin/python -m solbreaker prepare-client-registration --lab /path/to/prepared/client
```

Пароли сохраняются в SQLite как индивидуально посоленные PBKDF2-HMAC-SHA256-хеши.
Вход с неизвестной почтой требует регистрации. Повторное создание
существующего аккаунта отклоняется и сохраняет его прежний пароль.

## Резервные копии

GUI и TUI создают ZIP-архив в выбранной папке резервных копий. Сервер должен
быть остановлен. Архив содержит аккаунты, прогресс, конфигурацию и закрытый
ключ сервера. SQLite копируется через backup API вместе с данными из WAL.
Журналы, captures, runtime и lock-файлы в архив не входят.

```sh
.venv/bin/python -m solbreaker backup-state --state data --output backups
```

## Сеть и HTTPS

Новый сервер слушает loopback. Для второго игрока сначала настройте сетевой
профиль, затем запустите сервер и экспортируйте новое подключение.
Профиль подключения содержит адреса и публичный ключ сервера. Закрытый ключ,
пароли и папка `data/private` остаются у владельца.

### Автообнаружение

В разделе **Мой сервер → Настроить доступ по LAN / VPN** можно выбрать
адаптер общей сети. Остановите сервер перед сменой адаптера. Вариант
**Только на этом компьютере** возвращает доступ через loopback. Выбор
сохраняется в серверном состоянии. Если IPv4 хоста изменился, выберите
адаптер снова. Существующие игровые порты сохраняются.

Для поиска лаунчер посылает широковещательный IPv4-запрос на UDP 39068
или прямой запрос к устройствам из `tailscale status --json`. Ответ содержит
HTTP-порт Solbreaker. Лаунчер получает штатный профиль с HTTP-сервера,
проверяет сборку, отпечаток ключа и адреса и предлагает выбрать сервер.
В брандмауэре хоста разрешите UDP 39068, TCP API (по умолчанию 18080) и оба
игровых UDP-порта (по умолчанию 20016 и 20017) для выбранной сети.

- **Tailscale.** На обоих компьютерах должен работать локальный клиент
  Tailscale. На хосте выберите его адаптер. Политика tailnet должна разрешать
  указанные порты между игроком и сервером.
  [Документация Tailscale](https://tailscale.com/docs/reference/tailscale-cli).
- **ZeroTier и другие Ethernet VPN.** Поиск может работать, если адаптеры
  используют поддерживаемую частную IPv4-подсеть, а сеть пропускает broadcast.
  [Документация ZeroTier](https://docs.zerotier.com/protocol/#ethernet-virtualization-layer-vl2).
- **Radmin VPN.** Автопоиск и быстрый профиль LAN рассчитаны на частные
  IPv4 и CGNAT. Сеть Radmin с адресами `26.x.x.x` в этот режим не входит.
  [Справка Radmin VPN](https://www.radmin-vpn.com/help/index.html).
- **Маршрутизируемые VPN.** Для WireGuard и подобных сетей без broadcast
  используйте экспортированный профиль, если частный адрес сервера доступен
  через туннель. На роутере для LAN и VPN проброс не нужен.

### Игра по LAN

Для ручной настройки в примере у сервера IPv4 `192.168.1.10`, а локальная сеть использует
`192.168.1.0/24`. Подставьте свои значения. Разрешите входящие TCP 18080
и UDP 20016–20017 в брандмауэре хоста. Для LAN проброс на роутере не нужен.

```toml
version = 1

[listen]
http = "192.168.1.10:18080"
login = "192.168.1.10:20016"
base = "192.168.1.10:20017"

[advertise]
http = "http://192.168.1.10:18080"
login = "192.168.1.10:20016"
base = "192.168.1.10:20017"

[services]
http = "http://192.168.1.10:18080"

[access]
client_networks = ["192.168.1.0/24"]
```

### Игра через интернет

Используйте профиль v2 и HTTPS с действительным сертификатом. Откройте
выбранный TCP-порт HTTPS (обычно 443) и два UDP-порта игры (по умолчанию
20016 и 20017). Если сервер за роутером с публичным IPv4, пробросьте порты на
хост. При CGNAT одного проброса на своём роутере недостаточно. Возможные
варианты — публичный IPv4 у провайдера, хостинг с публичным IPv4 или общая VPN
с доступными внутренними адресами.

В `advertise` укажите адреса, достижимые со стороны игрока. Для login и base
нужны IPv4. Добавьте в `access.client_networks` адреса участников. Для
публичных IPv4 формат — отдельные `/32`. В список также должны входить
литеральные IP-адреса из `advertise` и `services`.

### Применение профиля

Подготовьте отдельный TOML и примените его к остановленному серверу
через **Параметры → Применить сетевой TOML** или из терминала.
Действующий профиль хранится в `data/network.toml`.

```sh
.venv/bin/python -m solbreaker configure-network --state data --config network.toml
```

Публичный профиль v2 поддерживает HTTPS с DNS-именем или IPv4. Игровые
login/base передаются отдельными IPv4-адресами. Пример
[network-public.toml](../examples/network-public.toml) предполагает HTTPS-прокси
перед loopback HTTP API. Замените демонстрационные IP, домен и список
допущенных клиентских адресов своими значениями. Сертификат и его продление
настраиваются на HTTPS-прокси.

При прямом TLS укажите HTTPS также в `services.http` и добавьте в manifest
пути `http_tls.certificate` и `http_tls.private_key`. Для собственного CA
доступно поле `tls_ca_file`. Пути считаются от папки состояния.
Проверка сертификатов выполняется в подготовленном клиенте.

## Настройки лаунчера

Пути хранятся в `runtime/manager.json`. Аргумент `--config` позволяет открыть
другой файл настроек. Сервер, запущенный из лаунчера, останавливается при
закрытии окна. Отдельно запущенный сервер управляется из своего терминала
или службы.

Для смены имени остановите сервер, откройте **Мой сервер**, введите имя
длиной до 48 символов и нажмите **Сохранить название**. После запуска
экспортируйте новый профиль, если игроки подключаются по файлу.

```sh
.venv/bin/python -m solbreaker configure-server --state data --name "Мой сервер"
```

## Песочница

Перед запуском включи **Мой сервер → Песочница во всех боях**. Из терминала
запусти `./start-server.sh --sandbox` или `.\start-server.ps1 -Sandbox`.
Участникам нужен клиент, запущенный через обновлённый лаунчер. Клавиши меняются
в **Настройки → Управление → Песочница Solbreaker**. Игра предупреждает, если
клавиша уже занята. Настройки сохраняются в профиле подготовленного клиента.
Для клавиш по умолчанию включи Num Lock.

- **Num 1** включает форсаж. Повторное нажатие его выключает.
- **Num 2** включает полёт. Управляй танком через WASD, поднимайся пробелом
  и снижайся через Ctrl. Повторное нажатие переводит танк на посадку.
  При повороте корпус наклоняется, а башня доворачивается вслед за прицелом.
- **Num 3** включает камеру ПТУР. Выстрели и управляй ракетой мышью.
  После попадания, окончания полёта или повторного нажатия камера вернётся
  к танку.
- **Num 4** ставит мишень в точке прицеливания на одиночном Полигоне.
  Наведи прицел на свободный участок земли. Мишени получают урон, а при
  таране их можно сдвинуть.
- **Num 7** меняет танк для следующих мишеней. Доступны копия твоего танка,
  Type 59, КВ-1 и Pz. IV. Всего на карте до семи мест, распределённых по типам.
- **Num 8** переключает ответный огонь для следующих мишеней. Они остаются
  на месте и стреляют, когда могут попасть в твой танк.
- **Num 9** очищает Полигон и освобождает все места для новых мишеней.
- **Num 0** восстанавливает прочность живого танка в любом бою с песочницей.

При включённой песочнице одиночный Полигон начинается без мишеней и длится
до выхода в ангар. Боезапас не расходуется, а после уничтожения своего танка
можно продолжить тренировку с точки появления.

Для «Гравитации» открой **Настройки боя → Правила боя → Гравитация** и начни
**Бой с ботами**. В этом режиме слабее притяжение и урон от падения, выше
скорость, а выстрелы отталкивают стрелка и цель. После отрыва боковой крен
плавно выравнивается. В воздухе **A/D** поворачивают корпус, а **W/S**
поднимают или опускают нос. Штатная **Способность 1** (по умолчанию
**7**) запускает ускоритель с земли у лёгких, средних танков и ПТ-САУ.
Ускоритель отображается в боевой панели и перезаряжается за 20 секунд.
Клавиша меняется в настройках управления.

## Правила боя и боты в тренировочных комнатах

При создании или редактировании комнаты нажми **Правила боя**, чтобы выбрать
«Встречный бой», «Превосходство», «Гравитацию» или «Перестрелку».
Для «Превосходства» выбери карту с точками захвата.

Запись `[bots 2:3]` в поле **Описание** добавит до двух ботов в первую
команду и до трёх во вторую. Если выбор режима уже добавил запись
`[mode gravity]`, поставь `[bots 2:3]` сразу после неё. Игроки занимают
места первыми. Обычно доступно по семь танков в команде, а у двух
вариантов Рудников со стартовыми точками 5×5 — по пять.

## Диагностика

Обычный журнал включается через `--log-file`. Подробный flight recorder
включается отдельно и записывает контекст кадров, сетевых событий и арены.

```sh
./start-server.sh --state data --log-file data/server.log --diagnostic-log
```
